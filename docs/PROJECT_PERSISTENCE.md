# 项目持久化与隔离

当前 MVP 按“一个项目一个工作空间”隔离抽取数据。项目是页面选择、上传材料和抽取记录的最小边界。

## 保存内容

- 项目名称和创建、更新时间。
- 每次抽取的文件名、材料用途、状态、模型、开始和完成时间。
- 上传的原始文件，路径按 `项目 ID / 抽取运行 ID / 文件名` 隔离。
- 完整五层抽取结果，包括每一步输入、提示词元数据、结果、耗时和汇总数量。
- 失败运行及经过标准化的失败原因。

浏览器只保存最近选择的项目 ID，用于刷新后恢复选择；业务结果以 API 数据库为准，不依赖 `localStorage`。

## 存储实现

本地和当前 Docker MVP 使用 SQLite 与 Docker 命名卷：

- 数据库：`/data/miaobi.db`
- 源文件：`/data/uploads/`
- Docker 卷：`miaobi-data`

服务启动时只创建缺失表，不删除或覆盖已有记录。重建镜像、重启 API 和 Web 容器不会删除命名卷。

## API 边界

- `POST /api/v1/projects`：新建项目。
- `GET /api/v1/projects`：项目列表。
- `GET /api/v1/projects/{project_id}/runs`：仅返回该项目运行。
- `GET /api/v1/projects/{project_id}/runs/{run_id}`：项目和运行 ID 必须同时匹配。
- `POST /api/v1/projects/{project_id}/extractions/run`：在指定项目上传并真实抽取。

跨项目读取同一个运行 ID 返回 404。API 不返回源文件服务器路径，也不返回模型密钥。

## 已验证

- 项目甲创建运行后，项目乙列表为空。
- 使用项目乙读取项目甲运行返回 404。
- 页面刷新后恢复最近项目和最新成功运行。
- API 与 Web 同时重启后项目和抽取结果仍存在。
- 真实 Qwen 抽取结果已在“五层抽取验证项目”中持久化。

## 当前边界

这是单用户 MVP 的项目级数据隔离，不是租户级安全隔离。进入多人生产阶段后，应将数据库切换到独立 PostgreSQL，增加用户、项目成员、行级权限、迁移工具和对象存储；前端项目概念和 API 路径可以保持不变。
